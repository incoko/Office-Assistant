## Context

本项目尚无应用实现，已有 `samples/` 中的虚构 Word、Excel、制度文本与验收说明。目标试点电脑已确认使用 Windows 10 x64、8GB 内存，安装软件时可由管理员运行安装程序并安装到 `D:\Program Files\Office Assistant\`；普通用户可以日常启动客户端。电脑不能访问互联网，模型由单位内网服务器提供。目标用户是单位 Windows 电脑上的非技术同事。

已确认产品为通用助手，第一版提供三个预置功能、保留高级配置与扩展能力，采用独立客户端而非团队平台。本设计不以具体银行制度为依据，也不代表已获得真实数据处理授权。

2026-09-23 接入信息更新：用户确认模型为 Qwen3.6，由 vLLM 部署；启动命令暂不可提供。现有 MCP 使用标准框架开发，配置指定 `sse` 及内网 `http://…/sse` 地址。以上为已报告部署信息，不表示已完成连接实测。`pg-mcp` 仅作为服务配置名称，不据此推断工具、数据库结构或读写权限；工具清单应在智能体配置服务后自动发现，不作为用户需预先提供的材料。

## Goals / Non-Goals

**Goals:**
- 通过同一智能体运行时完成三个预置场景，并实际验证增加智能体、导入 Skill、连接内网 MCP 的扩展路径。
- 普通用户通过选择助手、提供材料、预览和导出完成任务，不需要开发工具或配置文件编辑能力。
- 所有联网行为限于获准内网服务；所有本地执行经过权限检查；预置功能可离线安装。
- 定义可测试的文件来源、引用、任务状态、错误及输出行为。

**Non-Goals:**
- 不建设团队后台、身份权限平台、桌面自动化、任意脚本执行沙箱或外网扩展市场。
- 不部署模型服务器，不承诺兼容所有模型协议或第三方扩展。
- 不进行真实业务审批、操作或合规判断；不处理扫描件和任意表格格式。

## Decisions

### D1. 分层模块化客户端，而非三个独立功能程序

采用“工作台 → 应用服务/任务运行时 → 工具与连接适配 → 本地存储/文件/内网服务”的结构。预置助手通过配置引用能力，不能各自实现模型连接和权限逻辑。

```text
任务对话 / 快捷入口 / 高级设置
                ↓
应用服务：智能体配置、任务管理、权限确认
                ↓
运行时：模型适配、工具注册、调用校验、事件记录
       ┌────────┼──────────┐
       ↓        ↓          ↓
文档/表格工具  本地检索   内网模型与MCP
       ↓        ↓          ↓
    本地存储和授权目录   统一网络策略
```

备选的三个独立小工具交付路径简单，但会重复建设扩展和权限逻辑，不符合通用助手定位。微服务或团队后台增加部署负担，不进入第一版。

原型桌面框架采用 Python/Tkinter；Windows 打包链已确定为 CPython 3.12 x64 + PyInstaller onedir + Inno Setup 6.3+。PyInstaller 负责把解释器、Tk/Tcl 和应用依赖打入程序目录，Inno Setup 负责管理员机器级安装、快捷方式和卸载登记。该链必须在 Windows x64 构建机执行，macOS 开发机不能生成 Windows EXE；工具版本、wheel 和构建产物通过离线 bundle 固定并校验。

目标部署采用机器级离线安装：由管理员运行安装程序，安装到 `D:\Program Files\Office Assistant\`。客户端日常运行允许普通用户启动，不要求每次以管理员身份运行；任务访问文件时仍遵守当前用户的文件授权和应用自身的目录策略，不能因为安装程序以管理员运行就扩大模型、MCP、文件或工具权限。目标电脑按8GB内存基线设计，客户端应控制本地索引、任务缓存和文档处理的内存峰值。

本次试点不把应用白名单、内网证书要求、脚本或子进程限制作为环境前置条件。产品自身仍不得因环境没有这些限制而默认执行任意导入脚本、命令或桌面操作；执行能力继续由应用运行时的工具注册、参数校验和权限策略控制。

安装包不得借助管理员权限安装驱动、Windows 服务、系统级脚本运行环境或修改防火墙来绕过单位策略。安装目录与用户数据目录必须分离：安装文件放在 `D:\Program Files\Office Assistant\`，配置、凭据引用、任务记录、缓存和索引放在当前用户可写目录。必须先完成 Windows 10 x64、8GB 内存目标环境的离线安装、普通用户启动、内网连接和卸载验证，再形成技术选型记录；不得将单一开发机可运行视为交付完成。

### D2. 一套工作台，两层配置体验

首页提供通用对话、智能体选择和三个快捷入口；快捷入口只是预选智能体与输入表单。高级设置提供模型、智能体、Skill、MCP 和配置导入导出。

第一版不实现组织管理员身份。普通模式与高级模式是体验分层，不构成安全边界；运行时必须独立执行文件和网络策略。由维护人员提供不含密钥的预配置包，同事仍可在授权边界内创建自己的助手。

### D3. 模型与工具能力显式协商，不假定兼容

第一版以 Qwen3.6＋vLLM 为目标环境，优先适配 OpenAI 兼容 Chat Completions 接口；此处兼容是请求/响应格式选择，不代表连接外部服务。设置中保存实际服务地址、模型标识、凭据引用、超时和能力状态；不把“Qwen3.6”硬编码为服务必然接受的模型 ID，不推定具体规格、vLLM 版本、解析器或启动参数。

通过黑盒接口测试区分普通对话、`tool_choice: "auto"` 下的结构化工具调用、工具结果回传和流式工具调用。先用无副作用的模拟工具验证模型，再与动态发现的 MCP 工具联调；强制选择某个工具成功不替代自动选择测试，非流式成功不替代流式验证。缺少启动命令不阻止测试，不要求预先修改服务器配置。连接测试应区分网络/证书、认证、模型和能力不足；拿到实际地址与必要认证前，仅执行模拟契约测试，不标记真实能力已通过。

工具驱动场景必须通过结构化调用和参数校验；若服务缺少所需能力，明确禁用相关功能或将其列为接入阻塞项，不从普通回答中提取文本作为命令执行。连接失败禁止回退到外部模型。

采用受限工具循环，配置轮次、超时和输出大小上限。首次实现以单个活动执行任务为边界，不增加并行调度；历史任务可查看。使用内网服务不等于所有数据仅在本机处理，界面必须说明任务必要内容将发送至哪个批准服务。

### D4. 网络出口默认拒绝，配置与执行都检查

允许列表由部署配置确定，包括服务主机、端口、协议及允许的地址范围；普通配置包、模型回答、Skill 与 MCP 返回值不得扩大范围。首次没有有效策略时允许打开本地界面，但阻止联网并提示维护人员配置。

第一版默认优先使用经验证的内网 HTTPS 端点及单位信任链，不提供通用“忽略证书错误”开关。为兼容用户现有 HTTP＋SSE MCP，部署策略支持针对特定内网主机、端口和必要路径显式允许 HTTP；默认不允许任意 HTTP 目标，普通服务配置和配置导入不能创建例外。实际服务授权、认证、代理与证书在联调前确认；未配置认证字段不等于已确认无须认证。

所有请求执行前核验目标及解析地址。SSE 初始连接以及通过端点事件获得的消息提交地址都须经完整检查；提交端点使用批准路径范围，不将动态地址原样视为可信，也不因 /sse 获准就允许任意提交目标。禁止自动跟随未经检查的重定向；代理与认证地址亦须处于批准范围；不能只凭域名字符串或“看起来像内网 IP”放行。禁止外部遥测、崩溃上传、在线更新和页面远程资源加载。

运行时网络策略只承诺约束本应用和受控子进程，不替代单位操作系统或网络管控。远端模型/MCP 是否继续转发数据是客户端无法单独保证的边界，试点需确认服务侧处理约定。

### D5. 文件授权和受控工具取代任意代码执行

任务只能读取用户选择的文件、授权目录和显式导入的知识文档；目录授权须规范化真实路径并防止路径穿越及链接绕过。仅在指定输出目录新建文件，重名时另存，不覆盖或删除源文件。

生成前展示目标位置并取得任务范围授权；普通导出点击可作为本次写入确认。模型和文档不能增加权限。脚本型执行工具第一版只允许经过交付验证、固定入口和参数校验的预置工具，使用随包运行环境，限制时间、输出和继承环境，不暴露密钥。

用户导入 Skill 可以提供指令和参考资料，但其脚本不会因导入或启用而获得执行权。未支持依赖必须显示原因。任意本地命令、进程启动、桌面操作和业务提交工具不注册到第一版运行时。

MCP 工具按声明与测试结果配置权限，但不把服务声明作为可信安全保证。第一版只接入经批准的只读或无业务副作用的测试工具，不允许仅靠一次确认开放交易、邮件发送或业务写入。

### D6. 有限扩展范围与版本化配置

Skill 以本地目录导入，要求存在可读的 `SKILL.md`，解析支持的名称、描述和指令，校验目录内引用；导入采用本地副本，记录版本或内容指纹。第一版不做在线仓库下载。具体格式子集在实现前固定并编写兼容样例。

第一版实现现有旧式 HTTP＋SSE MCP 的兼容适配，不要求现有服务迁移；Streamable HTTP 仅预留传输扩展边界，不列为首版验收必需。本地进程 MCP 同样只预留适配接口，不实现进程管理。协议协商和认证按实际服务测试，未提供认证配置时保持“待验证”，不声称兼容全部服务。

配置支持表单填写及以下 `mcpServers` 嵌套结构导入；示例仅含脱敏占位符，不能视为可连接的真实地址，也不用于配置网络允许列表：

```json
{
  "mcpServers": {
    "pg-mcp": {
      "transport": {
        "type": "sse",
        "url": "http://<内网主机>:<端口>/sse"
      }
    }
  }
}
```

智能体绑定 MCP 服务后，由客户端验证连接策略并完成初始化，自动通过 `tools/list` 获取工具名、描述和输入模式，处理分页后展示发现结果。用户无需手填工具清单或预先解释业务用途；不根据 `pg-mcp` 名称硬编码工具、SQL 或数据库适配。发现结果经启用、绑定及任务授权后再映射为模型工具定义，模型提出调用后由运行时校验并通过 `tools/call` 执行，最后将结果回传模型。配置服务授权连接和发现，不等于授权调用所有工具。

允许手动刷新和重连后刷新工具目录。空列表显示“服务已连接但无可用工具”，发现失败则明确状态，不伪造工具或宣称执行可用；新增或变化工具按下述规则重新确认。通用适配验证使用模拟服务，真实服务联调时动态选择符合既定安全边界的工具，不要求现在提供 `pg-mcp` 工具明细。

扩展导入及配置恢复默认禁用新增工具。智能体只可使用“全局启用 ∩ 智能体绑定 ∩ 任务授权”内的工具。工具列表或参数模式发生变化时重新确认，不复用旧授权静默执行。

配置包包含格式版本、助手设置、Skill 引用及服务配置；不包含密钥、任务内容、文档正文和本机目录授权。不携带可扩大网络边界的信任策略。导入后需要本机补齐凭据、目录和信任确认。

### D7. 三个预置场景采用可核验执行路径

- **文稿整理**：读取用户粘贴的文字、文本或 `.docx`，按预置周报/纪要模板产生结构化草稿；未知信息明确标注。Word 导出由文档工具处理，文件输出仍经过授权。
- **表格检查**：只接受首批固定 `.xlsx` 模板，不执行宏、外部链接或公式。校验范围以样例“使用说明”为准；数字、日期、唯一性检查由程序执行，模型只组织解释。发现含公式的必填单元格时报告不支持并请求值化文件，不能把未计算缓存当作可靠结果。
- **制度查询**：导入少量 `.docx`、文本型 PDF 或文本文件，在本机构建索引，维护内容指纹、版本、章节定位。首版优先验证本地关键词/全文检索和分段上下文，避免额外引入尚未提供的嵌入服务；若样例检索不满足验收，再单独评估内网语义检索。发给模型的内容限于必要片段，答案引用须可定位到已导入原文。

制度无依据时说明未找到，冲突版本并列展示，不擅自决定效力；扫描 PDF 不调用外部 OCR。模拟制度始终显示虚构提示。

### D8. 本地记录、凭据分离与有限审计

逻辑实体包括 ModelConnection、AgentProfile、SkillPackage、McpConnection、Task、ToolCall、Artifact、KnowledgeDocument 和 PermissionGrant。每个任务记录配置快照或版本引用、状态、来源和产物，不将运行中任务随配置修改而隐式切换。

任务状态：待执行 → 执行中 ↔ 等待确认 → 成功/失败/取消。重启后未结束任务标为中断，不自动重放。取消必须停止后续调用并尽力终止正在执行的受控工具；不能保证撤回已送达内网服务的请求，界面需如实说明。

用户主动导入的资料、任务记录和产物保留在本地；诊断日志只记录最少的事件、错误码和脱敏路径，不记录密钥或完整材料正文。凭据存入操作系统提供的安全存储，普通配置只保存引用。提供本地历史清理入口，但不承诺安全擦除；不能连带删除用户源文件。UI 渲染将模型、文件和工具返回内容视为不可信数据，不执行其中脚本或加载外部资源。

## Risks / Trade-offs

- [已知 Qwen3.6＋vLLM，但实际工具能力未知] → 无需启动命令，先用模拟工具分别测试自动选择、结果回传和流式调用；失败则标记能力未通过，不引入外网回退或文本执行。
- [现有 SSE/HTTP 服务兼容性与动态提交地址] → 第一版优先实现 SSE，HTTP 仅特定目标显式放行，动态端点同样验证，不要求服务先行迁移。
- [安装和内存资源限制] → 目标电脑按Windows 10 x64、8GB内存和D盘Program Files安装路径验收；先用最小离线安装包与样例材料测量启动、文档处理和索引内存峰值，再扩展完整依赖。管理员安装权限不应转化为运行时的额外工具或文件权限。
- [导入扩展包含恶意指令或脚本] → 默认禁用新工具、限制格式、拒绝任意脚本、执行层校验权限，不信任提示词约束。
- [网络策略被重定向、代理或解析变化绕过] → 集中出口验证及负向测试，未知目标默认拒绝；部署策略与普通导入配置隔离。
- [远端服务二次转发不透明] → 纳入试点服务确认清单；客户端不作超出自身控制范围的保密保证。
- [制度幻觉、引用错配或过期文档] → 原文定位校验、版本展示、冲突提示和无依据测试；不定位为审批或合规决策工具。
- [文档兼容性和模型质量不稳定] → 限定首批格式和模板，预置样例回归，人工复核导出草稿。
- [普通/高级配置被误认为管理员权限] → 明确无身份隔离；如需组织级控制，另立变更，不能靠隐藏按钮实现。
- [通用能力预留导致范围膨胀] → 验收三个场景和三条扩展路径即可；不增加团队平台、通用沙箱和多智能体协作。

## Migration Plan

1. 记录已确认的目标环境和模拟材料授权；模型、MCP 地址、认证、数据流向和服务端处理约定不作为当前开发阻塞项，安排在功能开发完成后的内网部署测试阶段确认。
2. 先在开发/测试环境实现公共运行时与预置能力；随后由管理员在 Windows 10 x64、8GB 内存目标电脑将客户端安装到 `D:\Program Files\Office Assistant\`，由普通用户启动客户端，验证用户数据目录可写、内网连接与禁外网策略。
3. 用 `samples/README.md` 对三个场景回归；用独立的安全 MCP 测试服务验收扩展，不能只用内置工具代替。
4. 在没有开发环境的单位 Windows 10 x64、8GB 内存电脑上，由管理员完成安装、由普通用户运行试点，检查用户数据目录、重启、导出、网络请求、错误提示和内存占用。
5. 人工分发版本化安装包及不含密钥配置。升级前备份本地配置与索引元数据，存储格式变化必须提供迁移验证。
6. 回退时退出新客户端，恢复经过备份的配置/存储并安装旧版本；若无法安全兼容，保留原数据并阻止降级读取，禁止静默清空。第一版无已有线上数据迁移，但需验证安装、升级和卸载行为；卸载不得删除用户源文件及显式导出的产物。
